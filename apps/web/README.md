# @canvas/web

Фронтенд для редактора канваса на React Flow.

## Установка и запуск

```bash
# Из корня репозитория:
npm ci                        # установить все зависимости (включая @canvas/web)
npm run dev                   # запустить API на :4001
# В другом терминале:
npm run dev:web               # запустить фронтенд на :5173 (проксирует /api → :4001)
```

Собрать production:
```bash
npm run build                 # собирает API + web
npm run build:web             # только web
```

## Архитектура работы с API

Все HTTP-запросы проходят через одну функцию `request<T>()` в `src/api/client.ts`:

- Общий `fetch` с `Content-Type: application/json`, `X-Request-Id`, `Accept`
- Idempotency-Key передаётся опционально
- HTTP-ошибки, сетевые ошибки и ошибки парсинга нормализуются в `Result<T>` — дискриминированное union `{ ok: true, data } | { ok: false, error }`
- Компоненты **никогда** не делают `fetch` напрямую и не проверяют `response.ok`

Endpoint-функции (`api/spaces.ts`, `api/graph.ts`, `api/generations.ts`) — тонкие обёртки, описывающие только адрес, метод и особенности запроса. Проверка ETag, разбор ответа и обработка ошибок — в общем коде.

## Debounce и очередь сохранений

`useAutoSave` отслеживает `dirty` флаг в store. При изменении графа:
1. `dirty = true` → эффект запускает500ms debounce-таймер
2. При повторном изменении таймер сбрасывается
3. По истечении таймера `runSave()` сериализует граф и отправляет PUT
4. Если PUT в процессе — `inflightRef = true`, следующее сохранение откладывается
5. После завершения PUT, если были изменения во время запроса (`changedDuringSave`), `dirty` остаётся `true` и цикл повторяется

Перед генерацией `flushSave()` сбрасывает debounce и дожидается текущего сохранения.

## Сериализация графа — разбор производительности

`serializeGraph()` в `store.ts` — горячий путь перед каждым сохранением.

**Частота вызова:** раз в 500мс (debounce), не на каждый keystroke. При быстром вводе текста серия из20 keystroke'ов даёт один вызов.

**Проходы:** два отдельных цикла `for` — по нодам (n≤20) и рёбрам (n≤20). Итого ≤40 итераций. Один проход на каждый массив, без промежуточных коллекций. `.map()` не используется — `for` + `push` даёт тот же результат без аллокации callback-обёртки.

**Память:** на каждый нод — один объект `{ id, type, position, data }`, где `data` — ссылка на `{ text }` или `{ label }` (одно поле, без копирования `position`). На каждое ребро — `{ id, source, target }`. Промежуточных массивов нет. `viewport` передаётся по ссылке без копирования.

**Чего удалось избежать:** `stripNodeData` раньше создавал объект на каждый нод через отдельную функцию. Теперь data строится inline — тернарник `n.type === 'prompt' ? { text } : { label }` без вызова функции. Раньше было два `.map()` с лямбдами, теперь два `for`-цикла.

### flowNodes (стабильные ссылки)

`flowNodes` useMemo в `Canvas.tsx` — второй горячий путь. Вызывается при каждом изменении нод (перетаскивание, ввод текста).

**Проблема:** React Flow требует новые объекты для обнаружения изменений, но `{ ...n, data: { ...n.data } }` пересоздаёт ссылки на ВСЕ ноды при изменении ОДНОЙ. React потом re-renders все компоненты нод, даже если их данные не изменились.

**Решение:** кэш `Map<id, node>` в `useRef`. На каждый вызов — один проход по нодам, для каждой:
- O(1) lookup в кэше
- Если `data`, `position` и `type` совпадают (ссылочное равенство) — переиспользуется cached объект
- Если изменились — создаётся новый объект

При редактировании текста в одной ноде из5: пересоздаётся1 объект вместо5. При перетаскивании: пересоздаётся1 (position изменился). Неизменённые ноды сохраняют referential identity → React не перерендеривает их компоненты.

### isValidConnection (O(1) проверка рёбер)

`isValidConnection` вызывается React Flow при каждом движении мыши во время drag connection.

**Было:** `edges.some(e => e.source === id)` — O(e) на каждый вызов, + зависимость от `edges` в useCallback (пересоздание при каждом изменении рёбер).

**Стало:** `Set<string>` source-идов в `useRef`, обновляется через `useMemo([edges])`. Проверка `edgeSourcesRef.current.has(id)` — O(1). `isValidConnection` зависит только от `nodeMap`, не пересоздаётся при изменении рёбер.

## Проверенные сценарии

- Создание пространства, добавление/перемещение/удаление нод
- Связи prompt→generator→result с валидацией типов
- Автосохранение с debounce500ms
- Генерация с polling, отображение результата
- Восстановление после перезагрузки (граф + результаты + продолжение polling)
- Повтор failure-сценария
- 412-конфликт с кнопкой "Re-read graph"

## Известные недоработки

- Нет undo/redo
- Нет мобильной адаптации
- Нет drag-to-create связей из палитры нод
- Визуальный дизайн минимальный
